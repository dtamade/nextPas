# nextpas.core.js 设计审查报告 — 为什么 0.3 仍是“幼稚”

**审查人**：`codex/core-js` lane 自检 + 对标 `http/tui/crypto/json` 最佳实践
**时间**：2026-08-30
**版本**：S0 0.3 → 目标 1.0 前必须清零的差距
**结论**：0.3 已达“可评审骨架”，但距“生产级冻结”差 3 类硬差距 + 7 项幼稚病。若带病进入 S1，必在源码落地后返工。

---

## 1. 审查方法

- 标杆：`core/docs/http/CONTRACT.md 3.51`（82 单元、47 focused、INV-12 终局）、`tui/CONTRACT.md 1.30`（scorecard 30 项）、`crypto/CONTRACT.md 1.1`（INV-5 边界）、`json/CONTRACT.md 2.0`（双层视图）、`design-conventions.md §2/§3/§6/§8/§12`
- 检查维度：完整性、准确性、一致性、可验证性、可演进性、AI 工程化
- 判定：每项按 `通过 / 部分 / 缺失` 标记，`缺失` 即 S1 阻塞

---

## 2. 硬差距（S1 阻塞，必须在源码前清零）

| # | 差距 | 现状 0.3 | 后果 | 清零标准 |
|---|------|----------|------|----------|
| H1 | **无完整开发路线图** | `GOAL_TREE.md` 只有 S0–S4 标题，无里程碑日期、交付物清单、依赖图、风险缓解 | 无法排期、无法并行、无法评估人力 | 新增 `ROADMAP.md`：6 里程碑 × 交付物 × 依赖 × 风险 × 退出条件 |
| H2 | **无验收标准契约** | `CONTRACT §10` 只有门禁表，无 Definition of Done、证据链、回归策略、版本晋升规则 | 验收主观、回归无据、晋升随意 | 新增 `ACCEPTANCE.md`：DoD + 门禁矩阵 + 证据链 + 晋升规则 |
| H3 | **无现代 AI 开发规范** | 全文 0 处提及 agent/验证/提示词/审查纪律，回归到“手写代码+手写测试”前 AI 时代 | AI 生成代码无约束、审查无标尺、验证靠自觉 | 新增 `AI_GUIDE.md`：agent 工作流 + 提示词纪律 + AI 代码审查清单 + 验证前置 |

## 3. 幼稚病（7 项，部分阻塞）

| # | 病症 | 表现 | 修复 |
|---|------|------|------|
| N1 | **README 仍是营销稿** | 缺故障排查、FAQ、性能陷阱、版本兼容表 | README 增 § 故障/FAQ/陷阱/兼容 |
| N2 | **CONTRACT 无版本策略** | 未定义 semver、废弃周期、枚举尾部追加的二进制兼容影响 | CONTRACT 增 § 版本与演进 |
| N3 | **DESIGN 无备选量化** | 备选方案只有定性表，无量化（体积/启动/ABI 成本 ns/op） | DESIGN 增量化对比 + 决策日志 |
| N4 | **TESTING 缺失独立文档** | 测试策略散在 CONTRACT §10，无覆盖率目标、无模糊/属性测试、无 CI 矩阵 | 新增 `TESTING.md` |
| N5 | **SECURITY 仅 3 行** | 无威胁模型、无攻击面清单、无供应链（QuickJS so）审计 | 新增 `SECURITY.md` |
| N6 | **无基准方法论** | `bench_eval` 只有目标值，无测量方法、统计、回归阈值、对照组 | 新增 `BENCHMARKS.md` 或并入 TESTING |
| N7 | **文档间交叉引用断裂** | `README→CONTRACT→DESIGN→WEBVIEW_LINK→GOAL_TREE→PARITY` 链路存在，但 `ROADMAP/ACCEPTANCE/AI_GUIDE` 未挂入索引 | 修复 README 文档索引 + 新增文档互链 |

## 5. 现代 AI 工程缺口（专项）

| 规范 | 要求 | js 0.3 现状 | 风险 |
|------|------|-------------|------|
| Agent 工作流 | 明确 subagent 分工、worktree 隔离、任务恢复入口 | 0 提及 | 并行冲突、脏提交 |
| 提示词纪律 | 提示词版本、模板、可复现性 | 0 提及 | 生成漂移 |
| AI 代码审查 | AI 生成代码的强制审查清单 | 0 提及 | 缺陷流入 |
| 验证前置 | `verification-before-completion` 强制证据 | 仅口头 | 虚假完成 |
| 测试生成 | AI 生成测试的覆盖率与变异测试要求 | 0 提及 | 假覆盖 |
| 文档即代码 | 文档与源码的双向追踪 | 部分 | 文档腐烂 |

## 6. 处置建议

1. **S0 补课（本文档）**：新增 `ROADMAP.md` + `ACCEPTANCE.md` + `AI_GUIDE.md` + `TESTING.md` + `SECURITY.md` + `BENCHMARKS.md`，并将现有 6 份文档升级到 0.4。
2. **门禁**：`ROADMAP` 的 M1 退出条件即 `ACCEPTANCE` 的 S1 DoD，`AI_GUIDE` 的验证清单为 `make hygiene` 前置。
3. **下次审查**：S1 首个 `fake` 落地后，以 `REVIEW.md` 的 H1–H3 为回归项复审，未清零不得晋升 1.0。
