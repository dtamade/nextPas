## 2. 不变量
- Index: DIRC v2/v3/v4 + TREE 扩展，双遍精确尺寸序列化，SHA-1 全量校验；小写 split-index/sparse 扩展遇即拒绝（非跳过）。
- Cache-tree：记录解析（NUL 前缀、计数哨兵 -1）+ 两遍序列化，冲突失效整树粒度（与 git 最小目录失效语义等价——无效缓存必重算）。
- Status：HEAD↔index / index↔worktree / untracked 三态聚合 + rename/copy 检测（oid 100 快路径 + hashsig 0..100、阈值 50 配对、porcelain 分组序归并，conflict 跳过 rename；copy 需显式开启）+ .gitignore 链（`.git/info/exclude` + `core.excludesFile` + 逐级 `.gitignore`，`~/` 展开）+ submodule 目录校验；clean 另支持 `-d/-x/-n`。
- Wildmatch：`*/?/**/[]` 含转义/字符类零 `SysUtils`，`inline` 热路径（owner `text.wildmatch` 单源，git `ignore` 直连 `WildSegment*` inline 零拷贝，原 `git.native.wildmatch` shim 已移除）。
- Similarity 引擎（`status.similarity` 独立不变量，`bytes.ops` 单源零拷贝，缺能力反哺 owner）：`CMaxSimilarityBlobBytes=1MiB` 硬阈——`Size>1MiB` 直接跳过 `FillBlobSig` inflate 与 `ScoreFromSigs`（返回 -1，不读对象），避免瞬时 `TBytes` 峰值（1MiB×2 膨胀 + 行哈希 127 上限）与 `O(n·m)` 大文件配对风暴；代价为 >1MiB 文件重命名零覆盖（准确性权衡）；`HashForLine` FNV-1a 80 字节截断 + `CollectLineHashes` `TByteSpan.Slice` 零拷贝 + `SortU32` 单源 radix 127 cap + `ScoreFromSigs` 两指针归并 `O(CA+CB)`  capped 127，阈值 50 配对贪心最高分先配，一次配对，`isBlobMode` 仅 blob 参与。

## 3. 性能契约（复用 bytes.ops 单源）
- `Wild/Segment:inline|Class|SegmentsMatch:**` ≤100 ns/op（≥10 Mops/sec），单源 `text.wildmatch`，inline 零拷贝视图 `TByteSpan/PByte+Len`（`ignore`/`attributes` 直连 L1 owner，复用 `bytes.ops.GrowArrayCapacity`，原 shim 已移除单源直连）。
- Index 读写零重复 `ReadFile`（`Stat.mtime+size` 缓存 `TBytes`，见 commit-graph 复用模式）；`BytesConcatMany/SpanConcatMany` 单次分配防 O(n²) churn。
- Status 相似度：`CMaxSimilarityBlobBytes=1MiB` 硬阈——`Size>1MiB` 直接跳过 `FillBlobSig` inflate 与 `ScoreFromSigs`（返回 -1，不读对象），避免瞬时 `TBytes` 峰值（1MiB×2 膨胀 + 行哈希 127 上限）与 `O(n·m)` 大文件配对风暴；代价为 >1MiB 文件重命名零覆盖（准确性权衡）。阈值量化：源码仓 99% 文件 <1MiB（git 实测），大文件多为二进制，重命名误漏可接受；性能加分点：零拷贝 `TByteSpan` 视图 + 单源 `SpanHashFNV1a`/`SortU32`/`GrowArrayCapacity`，无额外 `inline` 循环体膨胀。
- **相似度独立契约与基准 SLO（`git.native.status.similarity` 候选，独立演进与压测，`bytes.ops`/`checksum.fnv32` 单源，`inline` 零拷贝，缺能力反哺 owner，不自建哈希/排序）**：`CMaxSimilarityBlobBytes=1MiB` 硬阈 + `ARenameThreshold=50`/`ACopyThreshold=50` 默认阈值 + `HashSigScore 0..100`（oid 100 快路径 + `100*2*matches/(a+b)` 行哈希 overlap，SMART 空白、80 字节截断、127 cap，`SortU32` 单源）三阈值单源可配；`Similarity/FillBlobSig` ≤5 µs/op（含单次 `TryGetObjectSize` + `ReadObject` inflate + `CollectLineHashes inline 零拷贝 slice` + 单 `SortU32` 单源 + 127 截断，`not inline` 守 I-Cache 重循环，`Size>1MiB` 零 inflate 快拒，`try..except EGitError` 不泄漏 `TBytes`）；`Similarity/ScoreFromSigs:inline` ≤100 ns/op（`O(127)` 两指针归并，零拷贝数组视图，`inline` 热路径，`Valid/Size>1MiB/ratio>8×` 三 guard 免哈希）；`Similarity/BuildBlobSigCache` ≤10 µs/100-entries（open-addressing `OidHash` via `bytes.ops SpanHashFNV1a` 单源零拷贝 `TByteSpan.Create(PByte(@Oid),20)` + `GrowArrayCapacity` 单源几何扩容，`not inline` 重循环守 I-Cache，`O(n) avg` vs `O(n²)` 线性扫描）；`Status/RenameOidFastPath:inline` ≤80 ns/op（≥12.5 Mops/sec，`GitOidSame inline SpanEqual` 零拷贝 via `bytes.ops` 三 QWord，oid 同值 100 免 `ReadObject`/`Collect`/`Sort`/`Score`）；`Status/RenameHashSig:1K` ≤5 µs/op（≥200 Kop/sec，`CollectLineHashes inline 零拷贝 TByteSpan.Slice` + `SortU32` 单源 radix 127 cap + `ScoreFromSigs inline merge O(CA+CB)`，`CMax1MiB` guard 免瞬时峰值，`bytes.ops` 单源，不触 `SysUtils`）；`bench_git Status/Similarity:*` 经 `nextpas.core.bench TBenchSuite` 单源 `10@200ms + 3 warmup + adaptive CV<5%` + 提交态 `baseline.json` 基线 + 绝对 SLO 双锚（`10-15%` 抖动余量，同机 `-O3 -Xs` 无 heaptrc 中位数，`ratio>1.10 && >2×CV` 判回归，`CV>10%` 则 `>1.15`），同总 CONTRACT §7 Go/Rust A/B 归一，可复现 `make -C core/benchmarks/nextpas.core.git/bench_git run`；`Write/*` 同理待抽 `bench_git Status/Similarity:1K|10K` 实测标定后晋升正式门禁，未达阈值前经 `test_git_native` 黄金覆盖（`GitCollectStatus rename/copy -M/-C` 阈值 50/1MiB 硬阈全量对照）。

## 4. 稳定性
- `IMappedFile` 计数拥有，`TPack/Index` 异常 `try..finally` 重抛不泄漏；`Status` 扫描 `fs` 句柄按目录 `try..finally` 关闭，`FillBlobSig` 经 `TryGetObjectSize` size guard 后 `ReadObject` 异常 `try..except EGitError` 快出且 `Valid:=False` 不泄漏 `TBytes` 瞬时峰值。
- 与对象层同 `EGitError` 单源 `native.base`；`Similarity` 引擎 `IMappedFile/TBytes` 零泄漏（`try..finally` + 接口计数，`HEAPTRC` 双 pin `haltonnotreleased` 零泄漏门禁同总 CONTRACT §6）。

## 5. 与总约关系
- 本域权威：暂存区状态/忽略规则/索引格式/相似度阈值以本文件为准；跨域仍以总 CONTRACT 为准。
- 缺能力先反哺 owner：路径/通配能力归 `bytes.ops`/`text.wildmatch`，哈希/排序归 `bytes.ops`/`checksum.fnv32`，暂存区仅编排（`status.similarity` 薄引擎 `inline` 零拷贝 `TByteSpan`/`SortU32` 单源，不自建压缩/哈希/通配）。
- 薄网关约束：`staging` 门面 `native.staging` <500 行 `inline` 零转发零分配，`similarity` 引擎拆分后 `status` facade 亦 <500 行，fan-in 经分片直引度量（`uses status.similarity` 单向，无循环）；持续监控阈值（`staging<500` / `status.similarity<500` / 单 shard<800，`scripts/git-contract-check.sh` C5）接近 800 软阈即再拆分。
