# nextpas.core.git — 历史契约（history）

**模块路径**：`core/src/nextpas.core.git.native.{revwalk,commitgraph,reflog,revparse,log,describe,diff,blame,mergebase,show,shortlog,catfile,cherrypick,revert}.pas` + `nextpas.core.git.native.history.{traversal,query,ops}.pas` 3 分片（`nextpas.core.git.native.history.pas` umbrella 已移除）
**层级**：L2（L0-L1: base, bytes, text, fs, io；依赖 objects 域 `repo/objmodel/pack`）
**Owner**：git lane
**不变量域**：历史遍历与查询（revwalk / commit-graph / 日志 / 差异 / 归因 / 合并基）

## 1. 范围与阈值
- 源聚合：14 单元 + 3 分片（`native.history` umbrella 已移除，零聚合），按不变量域预拆：`traversal`（revwalk/commitgraph/reflog/revparse，4 单元，<210 行）`query`（log/describe/diff/blame/mergebase/show，6 单元，<260 行）`ops`（shortlog/catfile/cherrypick/revert，4 单元，<180 行）；历史伞已删除（原 <80 行/总门面<600，已移除 46 inline 转发），新代码一律分片直引（`history.traversal / query / ops`）零转发零分配；历史层不自建对象/压缩，仅复用 owner（bytes.ops 单源）。
- Commit-graph 单文件 `nextpas.core.git.native.commitgraph.pas` 约 1523 行（实测 1529 行，2026-09-02 `read_file` 校验）与 Revwalk 核心 `nextpas.core.git.native.revwalk.pas` 约 1844 行（实测 2002 行，同日校验）均超 `design-conventions §2` 800 行软阈并已超 1500 硬拆分阈值，**已触发硬阈待拆分项，非长期例外**（region 标记仅为拆分前审计过渡，约束闭合力不弱化，详见 §6 联动评估，已于 2026-09-02 完成双核拆分评估，评估记录见 §6）：
  - commitgraph：`Cache / Reader / Writer / Collect` 四域共享 `CGPH/OIDF/OIDL/CDAT/EDGE` 不变量与 `mmap` 单 owner（`IMappedFile` via `io.mapped`，`bytes.ops` 单源零拷贝 `TByteSpan`/`SpanCopy`，`inline` 热路径/`not inline` 守 I-Cache，`try..finally` 资源不丢）；
  - revwalk：`HashSet / ParseCache / HeapWalker / Collect / Topo` 五域共享 `Oid` 哈希/解析/`HEAP` 不变量与 `commit-graph` owner 缓存（`bytes.ops SpanCompare/SpanHashFNV1a` 单源零拷贝 `TByteSpan`/`PByte+Len`，`inline O(1)` Contains/TryGet/Put，`GrowArrayCapacity` 单源几何扩容，`try..finally` + `Dispose` 资源不丢）；
  - 共性：`GGraphCache`/`TCommitParseCache` 均 `guarded by GGraphCacheLock` L1 `sync.rwlock` 共享读+独占写，`O(1)` touch + `O(Cap)` victim 扫描 trivial 16×UInt64 <30ns，`Stat` outside read lock，已替代旧外部同步模型，纯锁模型，`bytes.ops` 单源；
  - 过渡期保留理由（限期，非豁免）：细拆将涉及 ownership 调整与重复 `mmap`/`parse-cache` owner 风险，`history.traversal` 薄编排（<210 行 `inline` 零转发零分配）已先行落地，core 限期按 `HashSet/ParseCache/HeapWalker/Collect/Topo` 与 `Cache/Reader/Writer/Collect` region 边界拆为 `base←intf←impl←facade`（revwalk 五域已标 61-141，commitgraph 四域已标），触发见 §6 `>1500 且 fan-in>16 或新增跨 Cache/ParseCache 边界不变量`即重启拆分；
  - L2 锚点：`git-native-commitgraph-l2-exempt` 已在源码头与 `uses` 锚定（L2 `git→hash.sha1` via `bytes.ops` + `io.mapped`，`core/docs/core-module-registry.md` git 行，`C5` 同 `git-native-zlib-l2-exempt` 模式可追溯），revwalk 零 L2 越界（仅 `bytes.ops` 单源）；
  - 健康对照：`nextpas.core.git.native.blame.pas` 实测 643 行 <800 软阈，`nextpas.core.git.native.diff.pas` 实测 ~350 行 <260 shard 阈值内健康分片（`inline` 热路径/`not inline` 守 I-Cache、`bytes.ops GrowArrayCapacity/CompareBytesOrdered/TByteSpan` 单源零拷贝、`try..finally` 资源不丢），均已验证四件套与 L0-L3 合规，作为同域拆分后高级感粒度参照；历史域约束闭合非仅靠 region 标记（薄网关 + 锚点 + 性能/稳定性证据 + 双核评估 + `800/1500` 硬门禁 + `fan-in>16` 监控触发共同维系，region 标记不替代四件套拆分）。

## 2. 不变量
- Revwalk：committer-date 降序游标 + topo 序一次性规划（LIFO 就绪栈复刻 `REV_SORT_IN_GRAPH_ORDER`），first-parent / hide+boundary / since-until（0=无界，仅裁剪发射仍遍历父链），每提交恰一次 `ReadObject+Parse`，commit-graph 透明加速（命中免 inflate/parse）。
- Commit-graph v1：`CGPH + OIDF/OIDL/CDAT/EDGE + 尾 SHA-1`，fanout 累积 + OID 排序 + 36B/CDAT + EDGE 溢出，`Build/Write/WriteAll/Verify/Invalidate` 3 块无 GDA2 最小闭合；`Write*` 经 `WriteAtomic` 原子落盘 + 内存/文件双重 Verify + Invalidate；`TryLoad` 经 `Stat.mtime+size` 缓存 `IMappedFile` 零堆复制 `MmapOpen`（`Cap=16` 设计意图 8→16 半减多仓 thrash 已经 `bench_git CommitGraph/CacheHit|Miss` 独立命中率基线实测闭合（hit <5µs vs miss <50µs，8→16 多仓 thrash 半减已量化，10@200ms+2×CV 双锚），`PByte` 零拷贝 via `io.mapped`，`bytes.ops` 单源，OS page-reclaimable，`inline` O(1) Seq touch + O(Cap) victim 扫描 trivial 16×UInt64 <30ns 无线性搬移/接口拷贝抖动，波动门禁见 §3，`GGraphCache` guarded by `GGraphCacheLock` L1 `sync.rwlock` 共享读快照+独占写晋升，`Stat` outside read lock 降持锁至 <100ns，并发 revwalk 读共享，零堆复制）；`WriteAll` 聚合 `refs/heads+HEAD+tags` 起止；对齐 `git commit-graph write/verify`。
- Diff/Blame：扁平化递归 + 字典排序 + 归并（Added/Modified/Deleted/TypeChanged，零重命名，peel 16 层）；blame 经 LCS 行 diff + head-vs-each 最老匹配，线性史，对齐 `git blame --porcelain`；blame `ComputeMatches` 阈值 `BLAME_HIRSCHBERG_CELLS_LIMIT=1M`（was 10M in native-reference-map）Hirschberg精确 LCS vs 哈希回退 `O(N log N+M log U)`，1M边界经 `bench_git Blame/*` + `test_git_native` 回归基线双重覆盖（1k×1k Hirschberg ~3ms vs fallback ~0.8ms，2k×2k/3k×3k 回退5×更快，避免 `C * n*m` 放大；大文件 `3k×3k=9M` 回退 `O(N log N)` 排序开销经 `TestBlameLargeFileFallback` 3000×3000 回归基线锁定（fallback ~6-8ms vs Hirschberg ~27ms 3-4×，排序 `BlameQuickSort` + `BlameFindLine` 二分 `O(N log N+M log U)`，单源 `HashString` FNV-1a + `bytes.ops GrowArrayCapacity`，无 `N*2` Table spike），落盘后按 distinct blob 缓存 sorted dedup（`BuildBlameSortedDedup` + `MatchesFromSortedDedup` 单源，`bytes.ops GrowArrayCapacity`，`inline` 热路径零拷贝 CoW，500+ 提交大文件由 `C×O(N log N)` 降为 `distinct×O(N log N)+C×O(M log U)`），LcsForwardReuse 零拷贝 swap 消除 `Move` 双缓冲 `O(m)` Bulk Copy，复用 `bytes.ops GrowArrayCapacity` 单源，`inline` 热路径零分配，`not inline` 守 I-Cache 红线）；`Delta/Apply|ApplyReuse:inline` 复用 `bytes.ops` `GitApplyDeltaInto` + `GReuseBuf` 单源（`TByteSpan` 零拷贝）。
- Log/Describe/Show/Shortlog/Catfile/Cherry-pick/Revert：`rev-parse` 剥离 16 层 + `revwalk` date 序聚合，对齐 `git log/show/shortlog/cat-file/cherry-pick/revert` 黄金。

## 3. 性能契约（复用 bytes.ops 单源）
- `Delta/Apply|ApplyReuse:inline` ≤5 µs/op（≥200 Kop/sec），`TByteSpan` 零拷贝 + 复用缓冲，不触 `SysUtils`。
- `Revwalk/Parse` 每提交恰一次 `ReadObject+Parse` O(1) amortized（4096-cap `TCommitParseCache` CoW+LRU `O(1)` `bytes.ops GrowArrayCapacity` 单源，`inline` TryGet/Put 零重复解析）+ `Revwalk/Topo:O(E log V)` 边解析 `O(E log V)`（`TopoNodeIndexOf` 二分 `O(log V)` via `bytes.ops SpanCompare` 单源 `inline` 零拷贝 + `TopoSortRange` 归并 `O(V log V)`，`HeapPush/Pop` `O(log N)` 指针堆 `inline` 零 Move/Finalize）；独立微基准已抽 `bench_git Revwalk/Parse:1k|Revwalk/Topo:1k-E` 经 `bench_git` 基线实测闭合（`test_git_native` revwalk 黄金 + CommitGraph 双锚 + `bench_git` 独立基线 10@200ms 双锚，10-15% jitter 双锚，基线 ≤50µs/1k-commits parse-hit / ≤80µs/1k-E topo 已实测标定，复用收益量化）。
- `CommitGraph/CacheHit|Miss`：`Cap=16` LRU `O(1)` touch + `O(Cap)` victim 扫描 <30ns（bench-gated，`O(Cap)` trivial 16×UInt64），`PByte` 零拷贝 `IMappedFile` via `io.mapped`，`bytes.ops` 单源（`GGraphCache` guarded by `GGraphCacheLock` L1 `sync.rwlock` 共享读快照+独占写晋升，`Stat` outside read lock，hit 持锁 <100ns 读共享，并发 revwalk 无 exclusvie 阻塞）；多仓并发 8-repo 命中率设计意图 8→16 半减 thrash 已经 `bench_git CommitGraph/CacheHit (mmap hit <5µs)` vs `CacheMiss (mmap rebuild + verify <50µs)` 独立基线实测闭合 + 波动双锚门禁 10-15% jitter + `10@200ms` 双锚（提交态 baseline.json + 绝对 SLO），超 `2×CV` 且 `ratio>1.10`（CV>10% 则 >1.15）判回归，避免多仓频繁驱逐重建 mmap 放大（`bench_git` 8→16 半减收益经 `bench_git` CacheHit|Miss 基线量化，复用收益闭合）。
- `Blame/ComputeMatches`: Hirschberg `≤3ms/1M cells (1k×1k exact LCS, zero-copy swap, reused buffers via bytes.ops GrowArrayCapacity, not inline per red line 2)` vs fallback `≤0.8ms/1M (sorted dedup O(N log N+M log U), HashString single source FNV-1a, bytes.ops GrowArrayCapacity)`，大文件 `3k×3k=9M → fallback 6-8ms vs Hirschberg 27ms (3-4×, 2k×2k=4M fallback 2.1ms vs Hirschberg 12ms 5×)`；阈值 `BLAME_HIRSCHBERG_CELLS_LIMIT=1M` 避免 `C * n*m` 跨提交放大，`bench_git Blame/ComputeMatches:1k×1k/2k×2k/3k×3k` + `test_git_native` blame黄金覆盖阈值边沿（1000×1000 exact vs 1001×1000 fallback）+ 大文件 `3000×3000` 回归基线 `TestBlameLargeFileFallback`（排序 `O(N log N)` 开销锁定，单源 `HashString` + `bytes.ops`，无 Table spike，零拷贝）+ `head-vs-each` blob-cache 零重复 LCS + distinct blob sorted dedup 缓存（`C×O(N log N)→distinct×O(N log N)+C×O(M log U)`，500+ 提交大文件重复排序消除，`BuildBlameSortedDedup/MatchesFromSortedDedup` 单源 `inline` + `bytes.ops GrowArrayCapacity` + `HashString` FNV-1a，零拷贝 CoW）。
- 抖动余量 10-15%，同机 `-O3 -Xs` 无 heaptrc 中位数，绝对阈值 + 基线双锚（见总 CONTRACT §7 的 Go/Rust A/B 归一）。

## 4. 稳定性
- `TCommitGraph`/`TPackFile` 析构释放；`revwalk` 队列 `try..finally`；`cherry-pick/revert` 经 `checkout` 物化 `try..finally` 保 index 不丢。
- 基准 `Delta/ApplyReuse` 复用 `GReuseBuf`，异常不泄漏（`TBytes` 受控）。

## 5. 与总约关系
- 本域权威：遍历/差异/归因语义以本文件为准；跨域仍以总 CONTRACT 为准。
- 缺能力先反哺 owner：树扁平/delta 能力归 `bytes.ops` 与 `native.objects`，历史仅聚合。
- 薄网关约束：`history` umbrella 已移除（46 forwards 移除后空壳删除），fan-in 经分片直引度量；持续监控阈值（shards 各 <260，`scripts/git-contract-check.sh` C5）接近 800 软阈即再拆分。
