## 2. 审查流程

### 2.1 变更前准备
1. **需求分析**
   - 明确变更目标和范围
   - 评估影响范围
   - 确定优先级

2. **契约定义**
   - 定义接口契约
   - 定义错误语义
   - 定义线程安全保证

3. **测试编写**
   - 先写测试定义行为
   - 测试覆盖正常路径
   - 测试覆盖错误路径
   - 测试覆盖边界条件

### 2.2 变更实施
1. **代码编写**
   - 遵循编码规范
   - 保持单一职责
   - 避免重复代码

2. **自测验证**
   - 运行相关测试
   - 检查内存泄漏
   - 验证跨平台兼容性

3. **提交准备**
   - 原子化提交
   - 清晰的提交信息
   - 最小变更原则

### 2.3 Codex 审查
1. **审查内容**
   - 代码质量
   - 测试覆盖
   - 文档完整
   - 平台兼容

2. **审查标准**
   - 命名清晰
   - 职责单一
   - 无重复代码
   - 100% 测试覆盖
   - 0 泄漏
   - 接口契约完整

3. **审查流程**
   - 提交审查请求
   - Codex 审查代码
   - 反馈审查意见
   - 整改落实
   - 再次审查
   - 合入验证

### 2.4 合入验证
1. **验证内容**
   - 所有测试通过
   - 无内存泄漏
   - 跨平台兼容
   - 文档更新

2. **合入流程**
   - 创建合并请求
   - 自动化测试
   - 人工审查
   - 合入主分支

## 3. 审查标准

### 3.1 代码质量
- **命名规范**
  - 变量/函数命名清晰
  - 遵循 Pascal 通行风格
  - 避免缩写和歧义

- **职责单一**
  - 一个函数只做一件事
  - 一个模块只负责一个功能域
  - 避免上帝对象

- **无重复代码**
  - 发现重复立即提取
  - 使用公共函数
  - 遵循 DRY 原则

### 3.2 测试覆盖
- **测试类型**
  - 单元测试
  - 集成测试
  - 边界测试
  - 错误路径测试

- **覆盖率要求**
  - 行覆盖率 >90%
  - 分支覆盖率 >80%
  - 函数覆盖率 >95%

- **质量要求**
  - 测试独立性
  - 测试可重复性
  - 测试自描述性
  - 测试快速性

### 3.3 文档完整
- **接口契约**
  - API 签名
  - 参数说明
  - 返回值说明
  - 错误处理

- **错误语义**
  - 错误码定义
  - 错误消息
  - 错误处理建议

- **线程安全**
  - 线程安全保证
  - 并发使用指南
  - 同步机制说明

### 3.4 平台兼容
- **跨平台支持**
  - Linux x86_64
  - Linux aarch64
  - Linux arm32
  - Linux riscv64
  - macOS x86_64
  - Windows x86_64
  - FreeBSD
  - Android

- **兼容性测试**
  - 交叉编译测试
  - Wine 测试
  - QEMU 测试
  - 真机测试
