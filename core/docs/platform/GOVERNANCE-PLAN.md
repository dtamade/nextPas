## 3. 工作流程

### 3.1 变更流程
1. **需求分析**: 明确变更目标和范围
2. **契约定义**: 定义接口契约和错误语义
3. **测试编写**: 先写测试定义行为
4. **实现开发**: 实现满足测试
5. **Codex 审查**: 提交 Codex 审查
6. **整改落实**: 根据审查意见整改
7. **合入验证**: 合入并验证

### 3.2 提交规范
- **原子化**: 每次提交是一个逻辑单元
- **可追溯**: 提交信息清楚说明改了什么、为什么改
- **最小变更**: 禁止"顺手改"无关代码

### 3.3 审查标准
- **代码质量**: 命名清晰、职责单一、无重复代码
- **测试覆盖**: 100% 测试覆盖，0 泄漏
- **文档完整**: 接口契约、错误语义、线程安全
- **平台兼容**: 跨平台兼容性验证
