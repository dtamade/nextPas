## 性能瓶颈分析

### 1. Mean/100 仍有 256x 差距

**原因分析**:
- 接口调用开销：`GAnalyzer.Mean(GData100)` 通过 IBenchStatsAnalyzer 接口
- TBenchStatsAnalyzer 对象创建开销
- 基准测试框架本身的开销（计时、统计）

**优化方案**:
1. **SIMD 优化**: 使用 nextpas.core.simd 向量化计算
2. **内联优化**: 添加 `{$inline on}` 指令
3. **直接调用**: 绕过接口，直接调用实现类

### 2. StdDev/100 仍有 197x 差距

**原因**: 单次遍历优化已生效，但仍有其他开销

**优化方案**:
1. **SIMD 优化**: 向量化 Σx 和 Σx² 计算
2. **循环展开**: 每次处理 4 个元素
3. **减少函数调用**: 合并计算步骤

### 3. Sort/10000 已超越 Go！

**原因**:
- IntroSort 三数取中 pivot 避免最坏情况
- 插入排序对小数组高效
- FPC 编译器优化生效

**结论**: 大数据集排序是 Pascal 的强项！
