## 关键发现：数据测量偏差修正

### 问题根因

之前的性能报告存在**严重测量偏差**：

| 问题 | 原因 | 影响 |
|------|------|------|
| Mean/100: 432μs | benchmark 函数有内循环 1000 次 | 测量值放大 1000 倍 |
| 与 Go 对比不公平 | Go 使用单次调用，Pascal 使用内循环 | 导致 973x 差距的错误结论 |

### 修正方法

移除所有 benchmark 函数中的内循环，与 Go 的 benchmark 对齐：

```pascal
// 修正前（有问题）
procedure BenchMean100(const ACtx: IBenchContext);
var I: Integer;
begin
  for I := 1 to 1000 do        // 内循环 1000 次
    GAnalyzer.Mean(GData100);
end;

// 修正后（与 Go 对齐）
procedure BenchMean100(const ACtx: IBenchContext);
begin
  GAnalyzer.Mean(GData100);    // 单次调用
end;
```

## 性能分析

### 1. Sort 性能：Pascal 全面超越 Go

**原因**：
- IntroSort 实现优秀（插入排序 + QuickSort + 三数取中）
- FPC 编译器优化生效
- Go 使用标准库排序，可能未针对特定场景优化

**结论**：大数据集排序是 Pascal 的强项！

### 2. Mean/StdDev 性能：Pascal 非常接近 Go

**分析**：
- Mean/100: 107.6 ns (Pascal) vs 60 ns (Go) - **1.8x 差距**
- StdDev/100: 125.6 ns (Pascal) vs 94 ns (Go) - **1.3x 差距**

**原因**：
- 函数调用开销（接口调用 ~7ns）
- FPC 编译器可能未完全优化循环
- Go 可能有更好的指令调度

**结论**：差距很小，在实际应用中几乎可以忽略！

### 3. ComputeStats 性能：Pascal 全面超越 Go

**原因**：
- 内含 Sort (1,262 ns) + Mean (107 ns) + StdDev (125 ns) + Percentiles (~800 ns)
- Sort 性能优势直接体现
- 整体框架效率高
