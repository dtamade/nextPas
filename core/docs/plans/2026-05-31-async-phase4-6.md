# nextpas.core.async — Phase 4-6 Plan

> **目标:** 完善 async 模块测试 + 跨平台后端

## Phase 4: Async 深度测试（timeout 竞赛验证）

### 测试场景

1. **TestAsyncSleep** — 睡眠后回调触发，验证延迟精度
2. **TestReadTimeoutSuccess** — I/O 在 deadline 前完成（pipe 写入后读取）
3. **TestReadTimeoutExpired** — I/O 未完成，deadline 到期（pipe 无数据）
4. **TestWriteTimeoutSuccess** — 写入成功在 deadline 前
5. **TestTimeoutNoDoubleFire** — I/O 完成后 timer 不再触发
6. **TestTimeoutInfiniteDeadline** — Infinite deadline 等同无超时
7. **TestMultipleTimeouts** — 多个带超时的 I/O 同时进行
8. **TestTimeoutThenNormalIO** — 超时后继续正常 I/O
9. **TestCancelBeforeTimeout** — 取消 timer 后 I/O 正常完成
10. **TestZeroTimeout** — 0ms deadline 立即超时

### 质量门禁
- 所有测试 0 泄漏（TTimeoutCtx 正确 Dispose）
- 无 double-fire（IoCompleted/TimerFired 互斥）

## Phase 5: kqueue 后端（macOS/BSD）

### 文件
- `src/nextpas.core.io.reactor.kqueue.pas` — TKqueueReactor

### 设计
- kqueue + kevent（类似 epoll 的 readiness 模型）
- EV_ONESHOT（类似 EPOLLONESHOT）
- 与 TEpollReactor 相同 API
- 编译时 `{$IFDEF DARWIN}` 选择

### 依赖
- `nextpas.core.platform.darwin.base.pas` — kqueue 类型已定义
- 需要补充 kqueue/kevent syscall wrapper

### 测试
- 与 epoll reactor 相同的 6 个测试
- 需要 macOS 环境验证（或 compile-only gate）

## Phase 6: IOCP 后端（Windows）

### 文件
- `src/nextpas.core.io.reactor.iocp.pas` — TIocpReactor
- `src/nextpas.core.platform.windows.ffi.pas` — 补充 IOCP 函数

### 需要导入的 Windows API
```pascal
function CreateIoCompletionPort(AFileHandle, AExistingPort: THandle;
  ACompletionKey: UIntPtr; ANumberOfConcurrentThreads: DWORD): THandle;
  stdcall; external 'kernel32.dll';
function GetQueuedCompletionStatus(ACompletionPort: THandle;
  out ANumberOfBytes: DWORD; out ACompletionKey: UIntPtr;
  out AOverlapped: LPOVERLAPPED; AMilliseconds: DWORD): BOOL;
  stdcall; external 'kernel32.dll';
function PostQueuedCompletionStatus(ACompletionPort: THandle;
  ANumberOfBytes: DWORD; ACompletionKey: UIntPtr;
  AOverlapped: LPOVERLAPPED): BOOL;
  stdcall; external 'kernel32.dll';
function CancelIoEx(AHandle: THandle; AOverlapped: LPOVERLAPPED): BOOL;
  stdcall; external 'kernel32.dll';
```

### 设计
- IOCP = completion-based（类似 io_uring，不是 readiness）
- 每个 I/O 操作关联 OVERLAPPED 结构
- GetQueuedCompletionStatus 等待完成
- 与 TIoReactor（io_uring）更相似

### 测试
- 与 io_uring reactor 相同的 7 个测试
- 需要 Windows 环境（或 compile-only gate）
