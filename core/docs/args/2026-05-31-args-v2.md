# nextpas.core.args v2 — Subcommand Support Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Evolve nextpas.core.args into a production-grade CLI framework with subcommand routing, repeatable flags, required positionals, value validation, and global vs local flags — sufficient for `nextpas build/run/test/fmt`.

**Architecture:** Two-layer design:
- `TArgParser` (existing, enhanced) — single-command option/positional parser with schema validation
- `TArgApp` (new) — subcommand router with global flags, auto help/version, dispatch

Both are classes (§5: stateful service objects). Errors via exceptions (§4). Dynamic arrays (no fixed limits). No SysUtils dependency.

**Tech Stack:** Free Pascal (objfpc), `nextpas.core.errors`, `nextpas.core.text.number`, `nextpas.core.testing`.

---

## Phase 1: Enhance TArgParser Schema

### Task 1.1: AddStringList (repeatable flags)

Add `AddStringList(name, short, help)` for flags like `-I path1 -I path2`.
Add `GetStringList(name): TStringArray`.

### Task 1.2: Required flag / Required positional

Add `AddRequiredString(name, short, help)` — parse raises if not provided.
Add positional spec: `AddPositional(name, help, required: Boolean)`.

### Task 1.3: Value validation — Choices

Add `AddChoice(name, short, help, choices: array of string, default)`.
Parse raises if value not in choices.

### Task 1.4: Short flag cluster

Support `-vO2` expanding to `-v -O 2` (multiple short flags in one arg).

### Task 1.5: Duplicate name detection

`AddFlag/AddString/AddInt` raises if name or short already registered.

### Task 1.6: Auto --help / --version

Built-in `--help/-h` prints help and halts.
Built-in `--version/-V` prints version and halts (version set via `SetVersion`).

## Phase 2: TArgApp — Subcommand Router

### Task 2.1: TArgApp skeleton

```pascal
TArgApp = class
  constructor Create(const AName, ADescription, AVersion: string);
  procedure AddGlobalFlag(name, short, help);
  procedure AddGlobalString(name, short, help, default);
  function AddCommand(const AName, ADescription: string): TArgParser;
  procedure Run;  // parses os.Args, dispatches to command handler
  procedure RunFrom(const AArgs: array of string);
end;
```

### Task 2.2: Command dispatch

`Run` takes first positional as command name, routes remaining args to that command's parser.
Unknown command → raise with "did you mean?" suggestion (Levenshtein).

### Task 2.3: Global flags

Global flags (e.g. `--verbose`) parsed before command name, available to all commands.

### Task 2.4: Command handlers

Each command has a handler callback:
```pascal
TCommandHandler = procedure(const AParser: TArgParser);
procedure SetHandler(AHandler: TCommandHandler);
```

### Task 2.5: Auto help for app + commands

`nextpas --help` → list all commands
`nextpas build --help` → build command's help

### Task 2.6: Trailing args (-- separator)

`nextpas run main.pas -- arg1 arg2` → trailing args accessible via `TrailingArgs`.
