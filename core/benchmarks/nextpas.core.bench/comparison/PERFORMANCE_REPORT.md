## 分析

### 优势
1. **Sort 性能**: Go 的 sort.Slice 使用了优化的 pdqsort，Pascal 使用 QuickSort
2. **SIMD 优化**: Go 编译器会自动向量化，Pascal 需要手动 SIMD
3. **内存分配**: Go 的逃逸分析更成熟

### 待优化
1. **Mean/StdDev**: 可以使用 Kahan 求和减少浮点误差，但会增加开销
2. **ComputeStats**: 可以合并遍历减少内存访问
3. **SIMD**: 使用 nextpas.core.simd 模块优化热点路径

## 建议优化方向

1. **使用 SIMD 优化 Mean/StdDev**:
   - 利用 SSE/AVX 指令并行计算
   - 参考 nextpas.core.simd 模块

2. **优化 Sort**:
   - 考虑使用 IntroSort 或 Timsort
   - 对小数组使用插入排序

3. **减少内存分配**:
   - 预分配临时数组
   - 使用 arena 分配器

4. **编译器优化**:
   - 确保使用 -O2 或 -O3
   - 启用 LTO

## 结论

当前 nextpas.core.bench 的统计计算性能约为 Go 的 10-25%，主要瓶颈在于：
1. 缺少 SIMD 优化
2. Sort 算法不如 Go 的 pdqsort 优化
3. 浮点计算没有向量化

**建议优先优化**:
1. Mean/StdDev 使用 SIMD
2. Sort 使用更优算法
3. ComputeStats 合并遍历

框架开销方面表现良好：
- Fluent 配置: ~2us
- 空套件运行: ~3.8us
- 单基准运行: ~1.5ms

**注**: 以上 Pascal 性能为估算值，需要实际运行 bench_stats 获取准确数据。
