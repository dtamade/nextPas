# ADR 0001：冻结 nextPas 的 FPC 参考基线

- 状态：已接受
- 日期：2026-03-20

## 第一阶段只使用一个参考树

把 `/home/dtamade/projects/fpc` 作为 nextPas 第一阶段兼容性基线的唯一
真相来源。这样做是在仓库级别冻结外部参考，而不是依赖“当前安装了哪个 FPC”
或者跟随不断变化的上游目标。

这个基线很关键，因为 nextPas 是从一个空仓库起步的。在任何 `stage0` 驱动入口
或 RTL 工作变得可信之前，项目都需要一个明确的对照基准，来约束编译器结构、
运行时行为、包边界与测试套件预期。

## 第一阶段仅限 Linux x86_64

第一阶段只支持一个宿主和一个目标：Linux x86_64。这样可以让最初的
编译器驱动、测试、运行时契约与发行布局都围绕一个可重复的平台对齐。

FreePascal 已经支持很多 CPU 和操作系统，但 nextPas 不会把这份广度自动继承为
第一阶段义务。只有当 Linux x86_64 的证据稳定后，多平台扩展才允许开始。

## 把 FreePascal 作为 stage0

FreePascal 是 nextPas 的 `stage0` 实现工具链。第一版 nextPas 驱动入口、`harness`
和 smoke 路径可以运行在 FPC 之上，用于先建立项目自己的架构、契约和验证路径。

`stage0` 不是旁注，而是一条刻意选择的自举策略：它让项目先借助一个已知的
Pascal 编译器证明行为，再逐步接管更多管线责任。

## 把这些兼容层视为硬要求

以下层级是第一阶段硬要求：

| 层级           | 要求                                                    |
| -------------- | ------------------------------------------------------- |
| Source syntax  | 接受初始 smoke 套件和基线套件所需的 FreePascal 源码形式 |
| Core semantics | 保持基线测试依赖的语言行为                              |
| 单元/模块组织  | 保持 unit 发现与模块边界，足以支撑分阶段迁移            |
| RTL 行为       | 保持基线测试所需的可观察运行时行为                      |
| CRT 行为       | 让面向控制台的运行时行为保持显式，并可单独测试          |

以下层级暂时不是硬要求：

| 层级                       | 状态                                            |
| -------------------------- | ----------------------------------------------- |
| 完整包覆盖面               | 核心基线稳定后的分阶段后续工作                  |
| 全生态工具链对等           | 在编译器、运行时与 `harness` 基线证明完成前延后 |
| ABI / binary compatibility | ABI compatibility is deferred                   |

## 把这些内容排除在第一阶段之外

- No new syntax
- 不以 Delphi 对等兼容为目标
- 不提供 ABI 硬保证
- 不进行同步多平台首发
- 基线阶段不承诺包管理器、IDE、格式化工具或 LSP

这些排除项是护栏，不是遗漏。nextPas 首先是一个与 FreePascal 兼容的现代化
重构项目，而不是语法分叉，也不是“立刻全部替换”的计划。

## 这份 ADR 对下游的约束

- 所有架构文档都必须把 Linux x86_64 写成第一阶段唯一平台。
- 自举路线图必须把 FPC 视为 `stage0` 工具链。
- 兼容性矩阵必须把硬目标与延后事项分开写清。
- 测试套件必须把编译器、RTL、CRT 与回归行为都视为一等验证层。
