#### event 模块 — 进程内事件总线 ⏱️ 3-5 天

**设计参考**: Go `event` 包, Rust `tokio::sync::broadcast`

**API 设计**：
```pascal
// 事件总线接口
IEventBus = interface
  procedure Publish(const ATopic: string; const AData: TBytes);
  function Subscribe(const ATopic: string; AHandler: TEventHandler): ISubscription;
end;

// 或类型安全版本
IGenericEventBus<T> = interface
  procedure Publish(const AEvent: T);
  function Subscribe(AHandler: TGenericEventHandler<T>): ISubscription;
end;
```

**任务**：
1. 设计 API（与 /codex 讨论后确定）
2. 实现 `nextpas.core.event.pas`

## 设计原则

每个 L3 模块必须遵循：

1. **门面 API 风格**: 简单过程/函数一行搞定，或 Fluent Builder 链式调用
2. **错误处理**: 默认用异常，边界处统一捕获
3. **接口设计**: 小接口 + 组合接口（Rust trait / Go interface 风格）
4. **内存所有权**: 谁创建谁释放，interface 走 COM 引用计数
5. **线程安全**: 默认不线程安全，线程安全类型在文档中标注
6. **基准对照**: 每个模块对照 Go/Rust 标准库的公开 benchmark 数据

## 工作纪律

1. 每个模块必须：设计文档 + 单元测试（100% 接口覆盖）+ 0 leaks + 基准对照
2. 不绕过 system 模块直接调用 FPC RTL
3. 新模块开发先写设计文档，与 /codex 讨论后实现
4. benchmark 最后一轮再做，先完善和修复接口设计
5. 每个模块完成后 `make hygiene` PASS + git commit

## 关键约束

- L3 只依赖 L0-L2，不向上依赖
- 高层模块发现低层接口不顺时，通过受控跨模块修改推动低层收敛
- 不在高层堆 workaround 掩盖底层问题
- 所有 API 必须通过单元测试才算完成
